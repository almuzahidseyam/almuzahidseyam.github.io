n8n Gmail Cleanup Personal

Privacy policy

Updated 24 October 2026

This policy describes the personal Gmail cleanup automation operated by Muhammad Al-Muzahid on his own computer for his own account. It also explains the separate public documentation pages you are reading.

Data accessed and purpose

Through Google’s Gmail API, the automation accesses the connected account’s email address, message and conversation identifiers, dates, labels, message headers such as sender and subject, bulk-mail headers, attachment indicators and message snippets when returned. It uses these data to verify the account, identify old marketing mail and apply preservation rules.

The configured workflow requests conversation metadata. It does not download attachments or request complete message bodies. Metadata from other messages in a candidate’s conversation may be read so that conversations and replies can be preserved.

Selection rules

Cleanup considers reviewed senders and strictly qualified bulk promotions in Gmail’s Promotions, Social or Spam categories. For an unlisted sender, a marketing-style sender address, bulk-mail headers and an explicitly promotional subject are all required. Read and unread messages are checked against preservation rules for important labels, attachments, actual conversations and personal notices. The local execution state also stores the search query and next-page token to continue bounded scans; it does not grant additional Google access.

Permissions and actions

Google OAuth grants the https://www.googleapis.com/auth/gmail.modify scope. That scope permits reading and modifying email, including composing and sending. The configured automation uses only account checks, message listing, metadata reads and individual-message Trash actions; it does not send mail or permanently delete messages.

Eligible messages are moved to Gmail Trash. Google normally permanently deletes them after 30 days in Trash. Before then, the owner can restore them in Gmail. Conservative selection rules cannot guarantee that every decision is correct.

Where data are stored and for how long

Processing occurs in the owner’s local n8n installation. Google OAuth tokens and the client secret are stored in n8n’s encrypted credential database on that computer. The encryption key is also stored locally, so protecting the computer and any backups remains essential.

Execution records can contain account information, message metadata, sender addresses, subjects, snippets, decisions and error details. Automatic execution-data pruning is configured for 14 days. Local preview reports and any manually created backups are separate files; they remain until the owner deletes them. Google retains the mailbox and Trash according to its own settings and policies.

Sharing and other uses

The automatic workflow communicates with Google to retrieve data and perform the requested Gmail actions. It does not sell Google user data, use it for advertising, send it to AI services or use it to train AI models. It does not publish mailbox content on this website or share mailbox data with other third parties through the configured workflow.

The application’s use and transfer of information received from Google APIs will adhere to the Google API Services User Data Policy, including the Limited Use requirements.

Control, revocation and deletion

  1. Pause future cleanup by unpublishing or deactivating the workflow in local n8n.
  2. Revoke Google access in your Google Account third-party connections. Revoking access prevents future authorized API use; it does not remove existing local records.
  3. Delete the Google credential and execution records in n8n, then remove local preview reports and backups you no longer need. Removing the entire local n8n data directory also removes its workflows and stored credentials.
  4. Restore mistakenly selected messages from Gmail Trash within Google’s recovery window.

This documentation website

These static pages are hosted on GitHub Pages. They have no Gmail sign-in, forms, analytics scripts or application cookies, and they do not access visitors’ email. GitHub may process technical request information, such as IP addresses and access logs, when serving the website under the GitHub General Privacy Statement.

Changes and contact

This policy will be updated before the automation’s data use changes. If a change requires additional Google permission or consent, authorization will be requested before that new use begins.
